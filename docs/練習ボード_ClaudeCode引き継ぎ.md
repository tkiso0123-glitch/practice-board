# 練習・勉強会ボード　開発引き継ぎ（Claude Code向け）

作成：2026-11-12（Claude チャットでの検討内容のまとめ）
依頼者：木曽 稔之（キャリアコンサルタント養成講座の受講生）

---

## 1. 何を作りたいか（ひとことで）

キャリコン養成講座の同じクラスの仲間（LINEグループ・約20人）が、
**「この日のこの時間に、誰かと◯◯したい！」と手を挙げて仲間を集められるアプリ**。
人数がそろったら、LINEでみんなに知らせたい。

- 主な用途：**面談の実技練習（ロープレ）**。カウンセラー役・クライエント役・観察役の3人がそろうと成立
- ほかにも、もくもく勉強会、相談会、雑談会など、**テーマは自由に**開催できるようにしたい
- 本試験は2027年3月。それまでの練習の場づくりが当面の目的

## 2. 必須の要件

| # | 要件 | 補足 |
|---|---|---|
| R1 | URLをLINEグループに貼るだけで使える | 参加者に、パスワードや新しいサービスへの会員登録をさせたくない |
| R2 | 日時・テーマを決めて募集できる | テーマは選択肢（面談練習／もくもく勉強会／相談会／雑談会）＋自由入力 |
| R3 | 他の人が参加（手挙げ）できる | 参加の取り消しもできる。主催者は中止できる |
| R4 | 成立人数を会ごとに決められる | 面談練習の初期値は3人。定員も任意で決められる |
| R5 | 誰かが手を挙げたらLINEで知らせる | 「誰かが手を挙げた」「3人集まった（成立）」の2種類 |
| R6 | **木曽さんのPCを開いていなくても、常に動き続ける** | クラウドで動かす |
| R7 | 費用はできるだけかけない | 理想は無料。かかるとしても少額 |
| R8 | 管理者（木曽さん）が、不適切な投稿や間違いを消せる | |

## 3. LINE通知についてわかっていること（設計の前提）

※料金や仕様は変わることがあります。実装前に LINE Developers の公式ドキュメントで確認してください。

- **LINE Notify は2025年3月に終了**しているので使えない
- 自動通知は **Messaging API**（LINE公式アカウントのBot）を使う
- **ふつうのLINEグループに、公式アカウントをメンバーとして招待できる**
  - グループが公式アカウントになるわけではない。メンバーにBotが1人増えるだけ
  - 公式アカウント側で「グループ・複数人トークへの参加を許可する」をオンにする必要がある
  - BotがグループのIDを知るには、招待されたときの `join` Webhookイベントで `groupId` を受け取る
  - グループの発言がWebhookでBotに届くようになるので、**招待前にグループの了解をとる予定**（木曽さん側で対応）
- **通数の数え方（重要）**
  - Push／Multicast／Broadcast／Narrowcast は、**宛先の人数分**の通数としてカウントされる
  - **Reply API（返信）はカウントされない**（無料）
  - 無料のコミュニケーションプランは**月200通**まで。ライトプランは月5,000円で5,000通（税別）
  - **20人のグループに1回Pushすると20通**なので、無料枠では月10回まで
- **無料で告知する手段**
  - `https://line.me/R/share?text=...`：本人のLINEが文面入りで開き、本人が送り先を選んで送る。通数はかからない
  - LIFFアプリなら `liff.shareTargetPicker()` で、本人の名前でグループなどに送れる（Botの通数を使わない。仕様は要確認）
- **個別通知**：Botを友だち追加しているユーザーにだけ送れる。参加者だけに送れば、1回あたり2〜3通で済む

→ 方針：**「手を挙げた」の告知は本人が無料の手段で送り、自動通知は「成立」などの大事なものに絞る**。
自動通知は、無料枠に余裕があればグループに送り、残りが少ないときは参加者だけに送る。

## 4. これまでに検討・試作したこと

### 4-1. Claudeのアーティファクト（不採用）
書き込むには全員がclaude.aiにサインインし、招待を受ける必要があるので、R1を満たせない。

### 4-2. Google Apps Script（GAS）＋スプレッドシート＋LINE Bot（試作済み・未デプロイ）
同梱の `Code.gs`・`index.html`・`セットアップ手順.md` がこの試作版。模擬環境で主要な流れは確認済み。
実際のGoogle・LINE上では未検証。**仕様の参考として使い、作り直しは自由。**

試作で実装したこと：
- 募集（テーマ・日付・開始/終了・形式・場所・成立人数・定員・ひとこと）、参加、取り消し、中止
- 同じ会に同じ名前で二重に参加することを防ぐ。排他制御（LockService）
- 成立したら自動通知。取消で人数割れしたら「募集中」に戻して知らせ、再成立したらまた通知
- 通知先の自動切り替え（`FORMED_TO=auto`）：今月の残り通数と、グループ人数を取得するAPIを使って、グループか参加者だけかを判断する
- 個別通知の登録：Botに「登録 ニックネーム」と送ると、userIdと名前を紐づける（返信で応答するので無料）
- グループで「一覧」と送ると、予定一覧を返信する（無料）
- 「LINEで知らせる」ボタン（`line.me/R/share`）
- 最初に招待されたグループだけを通知先にする（あとから乗っ取られないように）
- 当日朝のリマインド（任意）

試作版の弱点（作り直したい理由）：
- **本人確認がない**：名前は自由入力で、取消は端末に保存したトークンで判定している。別の端末からは操作できず、なりすましも防げない
- **個別通知の登録が手作業**：ページの名前と、Botに送った名前が一致したときだけ届く
- **GASのWebhookはリクエストヘッダーを読めないので、LINEの署名（X-Line-Signature）を検証できない**
- 画面の自由度と表示速度：GASのWebページはiframe内で動き、表示がやや遅い
- データ置き場がスプレッドシート

## 5. アプリとして作り直すときの論点（Claude Codeで詰めたいこと）

以下は検討の材料です。決定事項ではありません。

### 5-1. 本人確認・入り口
- **案A：LIFFアプリ（LINEの中で開くWebアプリ）＋LINEログイン**（有力）
  - LINEで開くだけでuserIdとプロフィール名がわかり、R1（登録不要）と本人確認を両立できる
  - userIdがわかるので、個別通知の紐づけが自動になる
  - LINEログインのチャネルと公式アカウントを連携し、ログイン時に友だち追加を促せる（bot_prompt）
  - `shareTargetPicker` で、手挙げの告知を本人名義・無料でグループに送れる可能性
- 案B：本人確認なしのWebアプリ（試作版と同じ方式。手軽だが弱点も同じ）

### 5-2. 通知の手段
- LINE Push（グループ）：わかりやすいが通数がかかる
- LINE Multicast（参加者だけ）：安い。友だち追加が前提
- `shareTargetPicker`／`line.me/R/share`：無料。本人が送る操作が必要
- Web Push（PWA）：無料。ただしiPhoneはホーム画面に追加した場合だけ届くなど制約がある。補助として使えるかどうか

### 5-3. 動かす場所（R6・R7）
無料枠で常時動き、Webhookを受けられ、データベースがあるもの。例：
- Cloudflare Workers ＋ D1
- Supabase ＋ Vercel／Cloudflare Pages
- Firebase（Hosting ＋ Functions ＋ Firestore）※Functionsは有料プランが必要な場合あり。要確認
- GAS の延長（無料で手軽。ただし4-2の弱点が残る）

選ぶときは、無料枠で足りるか、LINE署名を検証できるか、木曽さんが保守できるか（なるべく手間が少ないこと）を重視。

### 5-4. データモデル（試作版ベースのたたき台）
- `events`：id, theme, title, date, start, end, style（オンライン/対面/どちらでも）, place, minPeople, capacity, note, hostUserId, status（募集中/成立/中止）, formedNotifiedAt, createdAt
- `participants`：eventId, userId, displayName, joinedAt
- `users`：userId（LINE）, displayName, isFriend（Botと友だちか）, notifyOptIn
- `settings`：通知モード、無料枠の残しておく通数など
- 終わった会のデータを一定期間で消すかどうか（個人情報を最小限にするため）

## 6. 画面・操作（最低限）

1. **一覧**：これからの会を日付ごとに表示。テーマで絞り込み。「あと◯名で成立」「成立！」の表示
2. **募集フォーム**：テーマ、タイトル、日時、形式、場所、成立人数、定員、ひとこと
3. **会の詳細／カード**：参加する、取り消す、（主催者は）中止する、LINEで知らせる
4. **管理者用**：投稿の非表示・削除、参加者を外す、通知モードの切り替え、今月の通数の確認

## 7. プライバシー・運用上の注意

- 講座の性質上、相談内容などの繊細な話題が書かれるおそれがある。フォームに「相談内容や個人的な事情は書かないでください」と明記する
- 保存する個人情報は最小限に（LINEのuserId、表示名、参加履歴くらい）
- グループのトーク内容は保存しない。Webhookでは決まったコマンドと `join` だけを処理する
- URLやBotはクラスの中だけで使う前提。外部の人が使える状態にはしない
- LINEのチャネルアクセストークンなどの秘密情報は、環境変数やシークレットで管理する
- Webhookでは署名の検証を必ず行う

## 8. 進め方の提案（MVP）

1. 動かす場所と本人確認の方式を決める（5-1・5-3）
2. 一覧・募集・参加・取消・中止を作る
3. 成立時の自動通知を作る（通数の自動切り替えも含める）
4. 告知を無料で送る仕組み（shareTargetPicker か share URL）
5. 管理者機能
6. 実際のLINEグループで、木曽さんと少人数でテストしてから全体に公開

## 9. 木曽さんに確認が必要なこと

- LINEグループにBotを招待してよいか（グループの了解）
- 費用の上限：無料にこだわるか、月数百〜5,000円程度なら許容できるか
- 講座の修了後も、同期の集まりとして続けて使うか（データの保存期間に関わる）
- 将来、ほかのクラスやコミュニティ（nuittoなど）にも広げる可能性があるか（作りの汎用性に関わる）
